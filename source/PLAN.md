# OAO 摄影社网站 · 修改计划书（定稿 v1）

> 状态：已获确认。技术路线、照片入库方式、权限、部署均已确定，见下方“已确认决策”。

## 一、目标

把现有纯静态展示页，升级为「**内部工具 + 对外传播平台**」一体站：

| 需求 | 落地方式 |
|---|---|
| 在线数据库 | 飞书多维表格（Bitable）作为唯一数据源 |
| 活动记录实时同步 | 站点写入 → 数据库即时更新；数据库改动 → 站点刷新即见 |
| 实时更新各大活动成果 | 首页统计 / 工作台 / 时间线 / 素材库全部改为读数据库渲染 |
| 链接百度网盘、自动化资料库 | “贴分享链接+提取码 → 自动生成资料卡”，资料库自动汇总 |
| 传照片时同步活动记录 | 上传动作同时写「照片表」并更新「活动表」的照片数 |
| 内部工具 + 对外传播 | 游客可看全部；成员口令登录后解锁上传/编辑 |
| 世外平台对接（不急） | 预留接口，通过飞书自动化/回调实现，最后做 |
| 小红书 / B站外链（不急） | 外链表 + 页面卡片 |

## 二、已确认决策

1. **技术路线**：飞书多维表格（在线数据库）+ 一个极薄的无服务器代理函数。
2. **照片入库**：两条路都支持——① 贴百度网盘分享链接（原件在网盘）；② 站内直接上传照片（存飞书附件）。
3. **权限**：游客可看全部 + 社团成员登录后编辑/上传。
4. **部署**：腾讯云函数（腾讯云）；MVP 登录用「统一访问口令」。

## 三、架构

```
静态站 (index.html / styles.css / script.js / app.js / config.js)
        │  读写（HTTPS）
        ▼
腾讯云函数代理 (cloud-function/index.js)  ← 保存飞书 App Secret，绝不进浏览器
        │  REST API（tenant_access_token）
        ▼
飞书多维表格 (Bitable)  ← 真正的“在线数据库” + 附件存储 + 自动化
```

- 密钥（App Secret、访问口令）只放云函数环境变量；前端拿到的是短时会话 token。
- 前端不重写，在现有玻璃拟态 UI 上加「数据渲染 + 上传表单 + 登录门」。

## 四、数据模型（飞书多维表格）

字段名与选项以 `SETUP.md` 为准，这里列结构：

**表 1 `activities` 活动记录**
活动名称（文本）、日期（文本，如 `2026.06`）、组别（单选：照片组/视频组/两者）、状态（单选：待选片/精修中/待交付/已归档/待剪辑/调色中/待发布/已发布）、类型（单选：舞台/运动/联动/公益/招新/课程/其他）、照片数（数字）、视频数（数字）、描述（文本）、封面（附件）、网盘链接（文本）、提取码（文本）。

**表 2 `photos` 照片素材**
活动（文本，按名称关联）、文件（附件，直接上传）、网盘链接（文本）、提取码（文本）、分类（单选：campus/sports/stage/collab/landscape）、说明（文本）。

**表 3 `links` 外链**
平台（单选：B站/小红书/其他）、标题（文本）、链接（文本）、备注（文本）。

> 网盘资料库不单独建表，挂在 `activities`/`photos` 的“网盘链接+提取码”字段上；资料库页 = 所有带网盘链接记录自动生成的卡片。

## 七、安全与取舍

- 飞书 App Secret / 访问口令只存云函数环境变量。
- 游客可看，写操作一律要求 `Bearer <token>`（登录后由云函数签发）。
- 提取码默认“点击复制”展示，不平面铺开（可选）。
- 直传附件公开展示走代理 `/api/file/:token` 中转，token 留在服务端。
- 单文件直传约 ≤ 4–5MB（受腾讯 API 网关 body 上限与 base64 放大影响）；大视频走网盘链接。
